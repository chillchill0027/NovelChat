# 魔法学院高级导入真机验证报告

验证日期：2026-08-01

故事文件：`advanced_story_import_magic_academy.example.json`

模型路由：剧情、剧情修订、任务分配、角色刷新均使用 DeepSeek `deepseek-v4-flash`

## 1. 导入覆盖

- 原创世界：雾海群岛与弦月秘仪学院。
- 主角：祁越；初始 NPC：迟霜、闻岚、陆砚。
- 导入内容：22 项显式字段定义，与兼容字段合并后共 39 项有效角色字段；8 条世界书、6 条世界规则。
- 首页指标：魔力储备、秘仪暴露、咒式稳定。
- 详情动态指标：灵脉状态、咒疲、反噬灼痛、心智负荷、奥术侵蚀、誓约张力。
- 长期判断指标：学院声望、断星线索。

高级 JSON 通过应用生产校验器并创建独立存档。应用冷启动后可恢复；姓名、身份、字段名称、范围、单位和显示位置均来自故事文件。

## 3. 叙事与状态一致性

- 多动作输入会按原顺序展开为环境、行动、人物反馈和直接后果，不再只复述用户句子。
- 第 9 轮正文完整写出抵达办公室、提交抄录、承认进入封印区、陆砚记录违规，并主动推进“封记更早被人改动”的线索。
- 第 10 轮完整写出受监督的低功率共鸣、潮纹响应、誓痕灼痛、立即中止和陆砚后续处置；状态同步对应更新魔力、稳定、侵蚀、誓约和疼痛。
- `ending_scene` 强制覆盖任务模型可能返回的旧地点与旧名册；第 8 轮在场角色清空，第 9、10 轮均收敛为陆砚。
- 每轮会把正文摘要写入 `scene_description`，避免地点已更新而场景说明仍停留在导入开局。

## 4. 测试中发现并修复的问题

1. 警报已触发但任务分配遗漏秘仪暴露。新增动态字段触发检查，缺失时要求任务分配重试。
2. 睡到清晨后遗漏恢复值和时间。新增休息/睡眠恢复与晨间时间的一致性检查。
3. 多次任务重试分别返回不同的有效字段，后一次会覆盖前一次。新增 `TaskAssignmentMergePolicy`，保留各次有效局部状态并让新值优先。
4. 英文 `partner` 被误解为恋人并创建顾宁。提示词现在要求无恋爱语境时按队友处理；该错误角色仅存在于修复前的测试存档，不在可导入示例中。
5. 第 9 轮地点和在场人物已更新，但场景摘要仍为旧教室。任务状态新增 `scene_description`，并由最终正文摘要确定性刷新。
6. 修复前第 10 轮初稿约 781 个非空白字符，两次通用“删改”没有扩长。长度不足现在使用专用扩写提示，保留更接近目标区间的中间版本；最终安装版重新生成第 10 轮时，823 字符的首稿经过一次专用扩写达到 1103 字符并通过质量门。连续修订后仍不在 1000-1500 字范围则不落盘。

## 5. 结论

高级导入能够把同一套角色卡接口改造成题材专属系统，并在剧情中按明确因果刷新。首页三项指标可以支持行动判断，详情字段能解释代价与恢复，事件字段不会每轮无意义抖动。十轮测试证明字段定义、初值、显示、任务分配、角色刷新、补同步和旧存档兼容能够共同工作。

本报告只记录通用机制，不包含 API 密钥。网络模型具有非确定性；应用以结构校验、动作覆盖、状态一致性、有限重试和未达标不落盘约束单次波动。
