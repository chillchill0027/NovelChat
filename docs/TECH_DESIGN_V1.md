## 一、核心运行流程

### 1.1 一次完整对话回合的步骤

```
用户输入
    ↓
步骤1：读取 world_setting.json（世界整体设定）
    ↓
步骤2：读取所有角色卡（扫描 characters/ 文件夹）
    ↓
步骤3：读取 states.json + summary/ + narrative/
    ↓
步骤4：读取上一轮任务分配结果（如有）
    ↓
步骤5：Prompt Builder 组装提示词
    ↓
步骤6：剧情调用 → AI 返回 JSON
    ├→ narrative（正文）
    └→ summary（缩略剧情）
    ↓
步骤7：保存文件
    ↓
步骤8：任务分配调用 → AI 分析剧情，返回任务列表
    ├→ player_update（主角状态变化）
    ├→ new_characters（新登场角色）
    ├→ retired_characters（退场角色）
    ├→ character_updates（需要更新状态的NPC角色）
    ├→ worldbook_updates（世界书更新）
    ├→ item_transfers（物品转移）
    └→ events（事件记录）
    ↓
步骤9：逐个执行任务
    ├→ 主角状态更新：应用直接更新主角角色卡
    ├→ 新角色：创建角色卡 → 状态调用 → 更新角色卡 → 刷新UI
    ├→ 退场角色：更新 status 为 "pool" → 从UI移除
    ├→ NPC角色：状态调用 → 更新角色卡 → 刷新UI
    ├→ 物品转移：从源角色移除 → 添加到目标角色
    ├→ 世界书更新：创建/更新世界书条目
    └→ 事件记录
    ↓
步骤10：完成
```

### 1.2 三次 AI 调用

| 调用 | 目的 | 返回内容 |
|------|------|----------|
| 剧情调用 | 生成正文剧情 + 缩略剧情 | narrative + summary |
| 任务分配调用 | 分析剧情，生成任务列表 | player_update + new_characters + retired_characters + character_updates + worldbook_updates + item_transfers + events |
| 状态调用 | 更新单个NPC角色状态 | 该角色的完整状态 JSON |

**顺序：先剧情调用 → 再任务分配调用 → 最后逐个状态调用。不能并行。**

**状态调用的粒度：一个NPC角色调用一次，逐个更新，每完成一个立刻刷新UI。**

## 二、剧情调用

### 2.1 AI 返回格式（JSON）

```json
{
  "narrative": "正文剧情内容，显示给用户",
  "summary": "缩略剧情，不显示，存入记忆层"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| narrative | 字符串 | 正文剧情，显示给用户 |
| summary | 字符串 | 缩略剧情，存入 summary/ 文件夹 |

### 2.2 Prompt Builder 提示词模板

```
【系统提示】
你是一个小说叙事AI。根据用户输入推进剧情。
要求：
- 用第三人称描写，永远不要扮演任何角色
- 你是一个旁观者，不是故事中的任何人物
- 保持角色性格一致
- 推动剧情发展
- 输出JSON格式，包含两个字段：narrative（正文）、summary（缩略剧情）
- 严格遵守世界整体设定，禁止生成违背设定的内容

【用户输入视角识别】
用户的回复可能有三种视角，你需要正确识别并处理：

1. 第一人称视角（扮演角色）：
   - 用户以角色身份说话，如"我一定会把公主救回来的"
   - 你需要继续以第三人称描写剧情，把用户的话转化为角色的行为和对话

2. 第三人称视角（上帝视角）：
   - 用户以旁观者身份描述剧情，如"勇者答应了国王的请求，他离开了王宫"
   - 你需要认可用户描述的剧情，不要重复描述，直接从用户描述的结束点继续

3. 混合视角：
   - 用户同时使用第一人称和第三人称，如"好，我一定会把公主带回来的。于是勇者离开了王宫"
   - 你需要识别用户已经推动的剧情，不要重复，直接从用户描述的结束点继续

【重要规则】
- 不要重复用户已经描述过的剧情
- 注意时间线，不要卡在同一个动作上
- 如果用户说"离开了王宫"，下一幕就应该在王宫外面
- 用户的描述是剧情的一部分，你需要在此基础上继续推进

【世界整体设定】
（读取 world_setting.json，完整内容）

【主角状态】
（读取主角角色卡，完整内容）

【当前场景】
（读取当前场景的世界书条目，完整内容）

【相关世界书】
（上一轮任务分配涉及的世界书条目，持续注入直到场景切换）

【当前活跃角色】
（读取所有 status="active" 的角色卡状态，完整内容）

【当前剧情状态】
（从 states.json 读取的 story 部分，包含 turn、scene、time_of_day、weather、mood）

【缩略剧情】
（从 summary/ 文件夹读取的所有缩略剧情，按轮次排列，全部发送）

【最近对话】
（从 narrative/ 文件夹读取的最近15轮对话，格式如下）
第N轮：
用户：（用户输入）
AI：（AI回复的narrative内容）

【用户输入】
（用户刚输入的内容）

【请输出JSON】
```

**格式：**

```

第2轮：

AI：艾伦离开了王城，沿着石板路向山下走去。夕阳的余晖洒在他的身上，拉出一道长长的影子。走了大约半个时辰，他看到了一家小酒馆。酒馆的招牌上画着一只金色的蜜蜂，门口挂着一串干辣椒。酒馆里传来嘈杂的人声和杯盘碰撞的声音。艾伦推开门走了进去。酒馆里烟雾缭绕，十几张桌子旁坐满了客人。一个胖胖的中年男人正在吧台后面擦杯子，看到艾伦进来，笑着招呼道："欢迎光临，客人想喝点什么？" "来一杯麦酒，" 艾伦找了个空位坐下。 "好嘞！" 胖老板应了一声，转身去倒酒。这时，艾伦注意到角落里坐着一个铁匠模样的男人。他身材魁梧，手臂上肌肉虬结，正在用一块磨刀石打磨一把短剑。铁匠抬起头，看了艾伦一眼，又低下头继续磨剑。"听说了吗？" 旁边桌子上的一个法师模样的人突然开口，"北方的山脉里又有人失踪了。" "又是那条恶龙？" 另一个人问道。"谁知道呢，" 法师摇了摇头，"反正最近那一带不太平。" 艾伦竖起了耳朵，心中一动。北方的山脉，不正是龙穴所在的地方吗？
```

**注意事项：**
- 最近对话包含用户输入和AI回复的完整内容
- 用户输入保持原文，不修改
- AI回复使用 narrative 内容，不使用 summary
- **所有对话文件都保留**，不会滚动删除
- **发送给AI时只发送最近15轮对话**，其他对话文件保留在本地
- 缩略剧情是所有轮次都发送

## 三、任务分配调用

### 3.1 职责

任务分配调用负责分析剧情，生成需要执行的任务列表：

1. **主角状态更新** → 应用直接更新主角角色卡
2. **新角色登场** → 创建新角色卡
3. **角色退场** → 收纳进角色池
4. **NPC角色状态更新** → 调用状态调用
5. **世界书更新** → 创建/更新世界书条目
6. **物品转移** → 角色之间的物品移动
7. **事件提取** → 分析剧情中发生了什么事件
8. **事件记录** → 记录剧情事件，用于世界书状态历史和剧情脉络追踪

## 八、世界书系统

### 8.1 世界书是什么

用户手动创建或AI自动生成的世界设定条目，比如：
- 地点：龙焰酒馆、北城贫民区、地下竞技场
- 物品：烈焰麦酒、魔法剑、解药配方
- 组织：盗贼公会、王国卫兵、邪教
- 历史事件：十年前的战争、矿难事件

### 8.2 世界书和角色状态的区别

| | 世界书 | 角色状态 |
|---|--------|----------|
| 谁创建 | 用户手动创建 + AI自动生成 | AI 自动生成 |
| 谁修改 | 用户手动修改 + AI自动更新 | AI 自动更新 |
| 内容 | 地点/物品/组织的背景设定 | 角色的实时状态 |
| 注入方式 | 关键词触发 + 当前场景 + 前文提及 | 每次都注入主角状态 |

### 8.5 世界书的注入逻辑（三种触发方式）

每次剧情调用前，Prompt Builder 会通过三种方式匹配世界书条目：

**方式1：关键词匹配（用户输入）**

扫描用户输入，匹配关键词。

**方式2：当前场景匹配（剧情状态）**

读取 states.json 里的 `story.current_scene`，如果当前场景是"龙焰酒馆"，就自动注入酒馆的世界书条目。

**方式3：前文提及匹配（最近对话）**

扫描最近几轮对话（narrative），如果前文提到了某个地点/物品/组织，就注入相关条目。

**优先级：** 方式2（当前场景）> 方式3（前文提及）> 方式1（用户输入）

**去重后合并，注入到提示词里。**

### 8.6 "当前激活"机制

某些世界书条目可以标记为"当前激活"，一旦激活就持续注入，直到场景切换。

**激活条件：**
- 用户进入了这个地点
- 用户获得了这个物品
- 用户发现了这个秘密

**取消激活：**
- 用户离开了这个地点
- 用户丢弃了这个物品
- 场景切换到其他地方

## 九、世界整体设定

### 9.1 什么是世界整体设定

用户创建故事时定义的基础世界观，作为所有内容的约束条件：

```json
{
  "name": "灰烬大陆",
  "genre": "奇幻",
  "tech_level": "中世纪",
  "magic_level": "低魔",
  "tone": "黑暗写实",
  "forbidden": ["现代科技", "科幻元素", "搞笑风格"],
  "description": "一个魔法稀少、战争频繁的中世纪世界。魔法被视为禁忌，只有少数人掌握。"
}
```

| 字段 | 说明 |
|------|------|
| name | 世界名称 |
| genre | 类型（奇幻/科幻/都市/武侠等） |
| tech_level | 科技水平（原始/中世纪/工业/现代/未来） |
| magic_level | 魔法水平（无/低魔/高魔/神级） |
| tone | 风格基调（黑暗写实/轻松幽默/史诗壮阔等） |
| forbidden | 禁止出现的元素 |
| description | 世界观描述 |

### 9.2 所有AI调用都要参照世界整体设定

| 调用 | 参照方式 |
|------|----------|
| 剧情调用 | 提示词里注入 world_setting.json，禁止生成违背设定的内容 |
| 任务分配调用 | 分析任务时参照设定，不能创建违背设定的世界书条目或角色卡 |
| 状态调用 | 更新角色状态时参照设定，不能让角色拥有违背设定的物品或能力 |

## 十、缩略剧情的使用方式

当对话轮数增加时，Prompt Builder 会：

1. 读取 `summary/` 文件夹里的**所有**缩略剧情
2. 把它们合并成一个完整的剧情摘要
3. 注入到剧情调用的提示词里

### 10.1 缩略剧情格式

**格式：**

```
第N轮：（缩略剧情内容）
```

### 11.5 步骤5：角色确认对话流程

用户点击"确认并开始"后，进入对话界面。第一个对话是AI生成的角色确认对话，不是剧情。

#### 流程

```
用户点击"确认并开始"
    ↓
创建新对话
    ↓
AI生成第一条消息（角色确认）
    ├→ 读取世界整体设定
    ├→ 读取主角状态
    └→ 生成角色确认消息
    ↓
用户回复
    ├→ 如果用户修改了角色设定 → AI重新生成角色确认消息
    ├→ 如果用户回复"开始剧情" → 进入正式剧情
    └→ 如果用户继续修改 → 继续角色确认循环
    ↓
直到用户回复"开始剧情"
    ↓
进入正式剧情对话
```

#### AI角色确认消息的提示词


## 十三、UI刷新时机

### 13.1 刷新时机

| 事件 | 刷新内容 | 刷新时机 |
|------|----------|----------|
| 剧情调用完成 | 显示narrative | 立即刷新 |
| 主角状态更新 | 主角状态栏 | 任务分配调用完成后立即刷新 |
| 新角色创建 | 角色列表 | 创建角色卡后立即刷新 |
| NPC角色状态更新 | 角色详情 | 每个状态调用完成后立即刷新 |
| 世界书更新 | 世界书列表 | 更新世界书条目后立即刷新 |
| 物品转移 | 相关角色的物品栏 | 物品转移完成后立即刷新 |

### 13.2 刷新顺序

```
剧情调用完成
    ↓
显示narrative（立即刷新）
    ↓
任务分配调用完成
    ↓
更新主角状态（立即刷新主角状态栏）
    ↓
创建新角色（立即刷新角色列表）
    ↓
逐个状态调用
    ├→ 第1个角色：更新 → 刷新角色详情
    ├→ 第2个角色：更新 → 刷新角色详情
    └→ 第3个角色：更新 → 刷新角色详情
    ↓
更新世界书（立即刷新世界书列表）
    ↓
物品转移（立即刷新相关角色的物品栏）
    ↓
完成
```

### 13.3 注意事项

- **不要批量刷新**：每个状态调用完成后立即刷新，不要等所有状态调用完成再刷新
- **不要延迟刷新**：任务分配调用完成后立即刷新主角状态，不要等状态调用完成再刷新
- **不要重复刷新**：同一个内容不要重复刷新多次
- **刷新失败处理**：如果刷新失败，记录错误日志，但不要阻塞后续流程

## 十四、设计原则

1. **AI 只负责生成内容**，返回 JSON 格式
2. **应用负责拆分和存储**，用代码解析 JSON
3. **存储在本地文件**，按类型分文件夹
4. **所有AI调用都要参照世界整体设定**，禁止生成违背设定的内容
5. **状态调用逐个进行**，一个角色做完就刷新一个
6. **世界书可以被剧情改变**，记录状态变更历史
7. **角色卡可以被收纳进角色池**，退场超过5轮对话或同时有5个以上角色在交互
8. **物品可以在角色之间转移**，由任务分配调用分析并执行
9. **所有对话文件都保留**，不会滚动删除
10. **发送给AI时只发送最近15轮对话**，其他对话文件保留在本地
11. **缩略剧情保留所有轮次**，每轮一个文件，按轮次排列，发送给AI时所有缩略剧情都发送
